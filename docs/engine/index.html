The Game Engine

What makes the top apps stick, one engine that turns any game idea into a game, and a map with a clear order. The 3D kingdom stays.

Research and blueprint. Nothing is built yet; the kids' URL is untouched.
Your words, 21 October: "any idea for a game is just pushed into the engine. It creates the game in the same, let's say, concept of the other games, but let's say different designs, different animals, and different tasks, and it grows as we want it."

In short

  • What the top apps do: you get the rules in seconds, you see yourself grow, every touch does something, rounds are short, and failing is funny. The learning games that work put the lesson inside that action instead of in a question box.
  • The engine: a game is a recipe of four parts: an action, a skill, a place and a ladder. The action is code, built once. The other three are data, so a new game is one new line, not a new build.
  • The map: every pin is a place, every place opens the same way (a row of games), and nothing opens a game inside another game. All the variety stays.

Your picks

  1. Which actions go into the engine first? My pick: Swallow & grow and Program the robot. One fast, one slow, as different as two games can be. If both run on one engine, any idea will. Program the robot already exists as Robot Diver.
  2. Rivals like Hole.io's other holes: characters only (a greedy goat, a pirate whirlpool), never other children, no leaderboards? My pick: yes. It keeps your rule "Don't compare it to other kids."
  3. The map shows places, and subjects show only in the parents' view? My pick: yes. Kids choose where to go; the engine makes sure the skills get mixed in.
  4. When an engine game covers a skill, does the old drill card for that skill go? My pick: hide it, don't delete it, and only after you have played the new one. The kids' URL changes only after your review.
  5. Which ages does the first build aim at? My pick: 5 to 9. Tell me if your kids are outside that.

What the top apps do

Kids' most-played game is Roblox: 139 minutes a day on average in 2024, according to Qustodio's data. The casual hits like Hole.io are built on a handful of rules that also show up in the learning games that work.

The engine

A game is a recipe. The action is the only part that is code. Skills, places and ladders are data, so one action plus a new line of data makes a new game.

ActionWhat the hands do: swallow, run, merge, aim, program… Code, built once.
+
SkillWhat decides right and wrong: make 10, the 8 times table, starts with ש.
+
PlaceWhere and who: the farm and a mole, the sky ocean and a whale.
+
LadderWhat changes each level, up and down: bigger numbers, faster, a new blocker.

Every round has the same shape

  1. The goal as a picture and a voice, in three seconds.
  2. Play 1 to 2 minutes. The skill is inside the action.
  3. Right: you grow. Wrong: a funny bounce.
  4. A twist halfway: a new rule or bigger things.
  5. The end shows what you made. No ranking.
  6. It goes home: the kingdom shows it.

The same controls everywhere (drag to move, tap to act), the speaker button in the same place, the way out in the same place.

Your 23 September rule still holds: "every world needs its own specific games … it can't be the same thing, otherwise it's boring." Places get different actions and their own look. Only the round's shape and the plumbing are shared, and kids never see those.

What the engine reuses from today's code: the question makers of the 17 worlds and shared/curriculum.js become the skills; KQ.ladder (levels that move both ways) becomes the ladder; the 3D halls, the cast, the realms' looks and the ElevenLabs voice stay.

Ten actions to pick from

Each card is one action the engine can learn. Fast actions drill facts the kid already understands. Slow actions build the understanding itself. A good kingdom needs both. Ask for more and there will be more.

Swallow & grow like Hole.io

Drag a hole around a busy place. It swallows only what fits the rule and grows with every right swallow, until it can swallow houses.

  • A mole on the farm swallows hay bales whose numbers add up to 10.
  • A whale in the Sky Ocean swallows fish from the 8 times table.
  • A whirlpool in Pirate Cove swallows treasure whose name starts with ש.

The map

Today the meadow has 50 pins, and 28 of them are on the first screen for a 6-year-old. Seven kinds of thing sit side by side, and several open a game inside a game.

Kingdom→Place→Game

Every pin is a place. Every place opens the same way: a row of its games, all made by the engine, plus one big button that plays the kid's next game, picked by the ladder. Nothing inside a game opens another game. Every one of today's 50 pins has a home:

Cost and build order

  • Money: no new monthly cost. The site stays on GitHub Pages (1 GB site limit, 100 GB a month of traffic, soft). The 3D art comes from the kits already in the game plus free CC0 models, like the Quaternius pirate ships. Spoken goals go through the existing ElevenLabs account and relay, with no extra credits (your 3 October rule). Voice batches stop when the credits run out.
  • First build, on staging only: the engine core, your two picked actions, and three recipes for each in different places with different animals. Then you play it.
  • Then: one action at a time. After that, a new game is a recipe line and usually needs no new code.
  • Effort (my estimate): the first build is one long working session, roughly 400 to 700 thousand tokens. Each new action after that is about half a session.
